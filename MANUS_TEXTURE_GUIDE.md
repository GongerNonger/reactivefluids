# Texture & Model Guide for Manus

This document describes exactly what textures and models are needed, what they should look like, and what format to use.

---

## Current State

All textures are **procedural placeholders** generated by `generate_pinata_textures.py`. They use flat colors with simple stripe patterns. They need to be replaced with proper piñata-style art.

### Texture Locations
```
src/main/resources/assets/reactivefluids/textures/
├── entity/pinata/       — Entity body textures (64 species × 2 = 128 files)
│   ├── whirlm.png       — Normal texture
│   ├── whirlm_sour.png  — Sour (dark/cracked) variant
│   ├── sparrowmint.png
│   ├── sparrowmint_sour.png
│   └── ... (one pair per species)
└── item/                — Item sprites
    ├── whirlm_candy.png — 16×16 candy item
    ├── sparrowmint_candy.png
    └── ... (one per species)
```

### Visual Style Requirements

**Normal textures** should have:
1. **Paper-mâché base**: Visible crepe paper fold lines (horizontal bands)
2. **Species coloring**: Based on the candy pun (see color palettes in VP_REFERENCE.md)
3. **Eyes**: Large round eyes with white sclera, dark pupils, small highlight dot
4. **Paper frills/seams**: Visible at segment boundaries
5. **Shading**: Darker on top/sides, lighter on belly
6. **No realistic detail**: Everything is stylized paper, not photo-realistic

**Sour textures** should have:
1. Same shape/layout as normal texture
2. **Darkened** colors (subtract 60-80 from RGB values)
3. **Cracks**: Visible crack lines across the body (dark lines/gaps)
4. **Red/angry eyes**: Replace normal eye color with red glow
5. **Desaturated**: Less vibrant than normal variant
6. **Slightly greenish tint**: Sickly look

### UV Layout Reference

For the most common model (PretztailModel / quadruped), the 32×32 UV map is:
```
(0,0)  - Body: 5×5×8 cube → occupies roughly top-left quadrant
(0,14) - Head: 4×4×3 cube + snout → below body
(14,14)- Ears: 2×3×1 → small
(18,0) - Tail: 3×3×6 → right side
(26,5) - Legs: 1×5×1 × 4 → right side bottom
```

For the bird model (SparrowmintModel), 32×32:
```
(0,0)  - Body: 6×6×7 oval → main area
(0,14) - Head: 4×4×3 + beak
(0,22) - Wings: 1×4×5 flat panels
(26,0) - Beak: 1×1×2
(26,4) - Legs: 1×2×1 sticks
(13,14)- Tail: 4×2×3 fan
```

## Candy Item Textures

### Specifications
- **Size**: 16×16 pixels
- **Format**: PNG with transparency
- **Style**: Wrapped candy shape — oval center with twisted wrapper ends on left and right
- **Colors**: Match the species' primary color
- **Details**: Single white stripe across the center, highlight on top-left, shadow on bottom-right

### Layout
```
     ╭──────╮
  ╲──│ CANDY │──╱
     │      │
     ╰──────╯
  wrapper  body  wrapper
```

## Spawn Egg Textures

Spawn eggs use vanilla Minecraft's built-in two-tone egg rendering. No custom texture needed — just the two hex colors specified in `ModPinataItems.java`:
```java
new DeferredSpawnEggItem(WHIRLM, 0xDC508C, 0xF08CB4, ...)
//                                  primary   secondary
```

## Model Notes

Currently all species share one of 9 Java model classes. Ideally each species would eventually get a unique model. The recommended approach:

1. **Use Blockbench** (blockbench.net, free) to create `.geo.json` models
2. **Add GeckoLib** dependency for animation support
3. Export models in GeckoLib format
4. Each species gets: `[species].geo.json` + `[species].animation.json` + `[species].png`

For now, the Java models work but produce very blocky Minecraft-style shapes. The textures should be designed to look good on these blocky shapes — emphasize bold colors and simple patterns rather than fine detail.
